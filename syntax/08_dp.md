# 08 — DP Syntax (memo → tabulation → space-opt)

> All DP = same 3 steps: **define state → base case → transition**. Learn these 4 shapes, everything else is a mix.

## Shape 0 — 1D (fib, climb stairs, house robber)

```cpp
// MEMO (top-down): recursion + cache
vector<int> dp(n+1,-1); // -1 = not computed
int f(int i){ if(i<=1) return i; if(dp[i]!=-1) return dp[i]; // base + cache hit
  return dp[i]=f(i-1)+f(i-2); } // transition = combine subproblems
```

```cpp
// TABULATION (bottom-up): loop from base
dp[0]=0; dp[1]=1; for(int i=2;i<=n;i++) dp[i]=dp[i-1]+dp[i-2]; // same transition, no recursion
```

```cpp
// SPACE-OPT: keep only last 2
int prev2=0,prev1=1; for(int i=2;i<=n;i++){ int cur=prev1+prev2; prev2=prev1; prev1=cur; } // O(1) space
```

## Shape 1 — Knapsack / subset (take-notake on index+capacity)

```cpp
int f(int i,int W){ if(i==0||W==0) return 0; // base: no item or no space
  if(dp[i][W]!=-1) return dp[i][W]; // memo check (init dp with -1)
  if(wt[i]<=W) return dp[i][W]=max(val[i]+f(i-1,W-wt[i]), f(i-1,W)); // take vs skip
  return dp[i][W]=f(i-1,W); } // too heavy → skip
```

```cpp
// Tabulation: dp[i][w] with dp[0][*]=dp[*][0]=0, loop i 1..n, w 0..W — same max() line
```

## Shape 2 — Grid (unique paths, min path sum)

```cpp
// dp[i][j] = answer for cell (i,j); from top/left only:
dp[0][0]=grid[0][0]; // base cell
for(int i=0;i<R;i++) for(int j=0;j<C;j++){ if(i==0&&j==0) continue;
  int up = i>0?dp[i-1][j]:1e9, left = j>0?dp[i][j-1]:1e9; // missing neighbour = INF
  dp[i][j]=grid[i][j]+min(up,left); } // transition: best of two parents
```

## Shape 3 — Strings (LCS / edit distance)

```cpp
// dp[i][j] = answer for s[0..i), t[0..j)
for(int i=1;i<=n;i++) for(int j=1;j<=m;j++)
  if(s[i-1]==t[j-1]) dp[i][j]=1+dp[i-1][j-1]; // chars match → extend diagonal
  else dp[i][j]=max(dp[i-1][j],dp[i][j-1]); // else best of top/left
```

## How to take DP input

```cpp
int n; cin>>n; vector<int> a(n); for(int &x:a) cin>>x; // 1D DP input
int W; cin>>W; // knapsack capacity comes after array
// grid: int R,C;cin>>R>>C; vector<vector<int>> g(R,vector<int>(C)); read nested loops
// strings: string s,t; cin>>s>>t;
```

## LIS O(n log n) snippet (patience)

```cpp
vector<int> tails; // tails[k] = smallest tail of increasing subseq of length k+1
for(int x:a){ auto it=lower_bound(tails.begin(),tails.end(),x); // first >= x
  if(it==tails.end()) tails.push_back(x); else *it=x; } // extend or replace
// answer = tails.size()
```

## 6 Must-Do Problems (sufficient for this topic)

1. **Climbing Stairs (LC 70)** — Input: `n=5` → `8`. Why: Shape-0 fib pattern. Do memo → tabulation → space-opt all three — 15 mins, DP clicked.
2. **House Robber (LC 198)** — Input: `[2,7,9,3,1]` → `12`. Why: Shape-0 with skip choice `max(take,skip)`. Base for Robber II (circular = two runs).
3. **0/1 Knapsack / Partition Equal Subset Sum (LC 416)** — Input: `[1,5,11,5]` → `true`. Why: Shape-1 take-not-take on `(i,target)`. GFG knapsack + this LC are same code.
4. **Unique Paths + Minimum Path Sum (LC 62, LC 64)** — Why pair: same Shape-2 grid template, only transition differs (`sum` vs `min+grid`). Do 62 then 64 back-to-back.
5. **Longest Common Subsequence (LC 1143)** — Input: `"abcde","ace"` → `3`. Why: Shape-3 diagonal-vs-top/left. Base for Edit Distance, Longest Palindromic Subseq.
6. **Longest Increasing Subsequence (LC 300)** — Input: `[10,9,2,5,3,7,101,18]` → `4`. Why: O(n²) take/skip first, then `tails+lower_bound` O(n log n) snippet from this file. Coin Change (LC 322) as bonus — same 1D but min-transition.
